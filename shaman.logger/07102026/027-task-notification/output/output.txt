I've added XAI to the design and documented it. Nothing is coded yet.

**What's new in the docs**
- **`docs/xai.md`:** the full design. Every recommendation answers *Why?*, *Why not?* and *What if?*, using each model's actual internals rather than a separate tool guessing afterwards.
- **`features.md` §8.4:** a summary of the design.
- **README:** a 7th "what makes it different" point, XAI by design, tied to MeitY's *"Understandable by Design"* principle in India's AI Governance Guidelines (November 2025).

**What XAI covers in each module**

| Module | Already built | New in the design |
|---|---|---|
| **Decision engine** | shadow prices, `why_not`, Pareto frontier | • which limits held the plan back (binding constraints)<br>• each course's contribution, and the loss if it were dropped<br>• counterfactuals, e.g. *"₹40K more and ml201 gets chosen"*<br>• the smallest set of conflicting constraints when no plan is possible (CP-SAT supports this)<br>• how the plan holds up across low/high demand forecasts |
| **Forecasting** | demand pattern, prediction intervals | • the reason each model was picked<br>• backtest leaderboard<br>• trend/seasonality breakdown (MSTL)<br>• SHAP only once feature-based ML exists (V2+) |
| **Skill extraction** | the evidence clause, lexical/semantic flag, similarity | • highlighted words<br>• runner-up skills for one-click correction<br>• calibrated confidence |
| **Gaps and briefs** | none | • gap-score waterfall (demand × shortfall)<br>• data sources<br>• sentence-level citations<br>• faithfulness report |

**Across all modules:**
- one shared `Explanation` format
- a "Why?" button on every number
- the Evidence Trail view
- an audit log
- model cards

**The SLM fits in:** it receives these computed explanations and turns them into readable text. It never makes up reasons.
